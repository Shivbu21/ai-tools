# Payment Screenshot Verifier

Upload a UPI payment screenshot → get a forensic **indicator** report (metadata,
Error-Level Analysis heatmap, layout heuristics, risk score with every
contribution explained).

> ⚠️ **HONEST WARNING — READ FIRST**
> These are **indicators of possible tampering, NOT proof**.
> A **clean score does NOT guarantee authenticity** — a careful forgery can score low.
> A high score does **not** prove fraud either.
> **Never use this as the sole basis for financial decisions.**
> Always verify the transaction in your own UPI app / bank statement.

## One-command run

```bash
cd payment-verify
pip install -r requirements.txt
python3 make_samples.py   # (optional) regenerate the test images
python3 app.py            # open http://127.0.0.1:5000
```

CLI usage:

```bash
python3 forensics.py samples/tampered_receipt.jpg report_heatmap.png
```

## How each check works (all really implemented in `forensics.py`)

**1. Metadata (weight 15).** Extracts EXIF / PNG info chunks / JPEG tables with
PIL and reports presence or absence. Most phone screenshots *do* carry metadata;
chat apps (WhatsApp/Telegram) usually strip it on forward — so stripped metadata
is only a *mild* flag, never a verdict. EXIF is trivially forgeable, so its
presence proves nothing either.

**2. Error-Level Analysis (weight 40).** Re-saves the image as JPEG quality 90,
takes the absolute luma difference vs the original, and renders a black→red→yellow
heatmap PNG. Then:
- the JPEG save quality is **estimated from the quantization tables** (matched
  against standard IJG tables),
- 24px grid cells are scored; seed mask = cell error > max(2×p75, 0.5),
- 4-connected components are built; a component is flagged **suspicious** iff it
  is large (≥20 cells — a forged amount block is a fat blob, natural text strokes
  are thin) AND hot (mean cell error > 2.3) AND does not stabilise under ELA at
  the image's own estimated quality (mean > 0.06 there). Genuine same-pipeline
  content goes near-zero at its own quality; pixels composited from a
  differently-compressed source do not.

**3. Layout/template heuristics (weight 20).** Structural checks only, labelled
as such: aspect ratio vs known GPay/PhonePe/Paytm receipt bands, header-vs-body
brightness contrast, texture of the amount zone. Fonts, logos and glyphs are
**not** checked — a forgery made from the real app passes this.

**4. Dimensions (weight 10)** and **5. file size (weight 5).** Sanity signals
(e.g. unusual resolution, quality-laundering-sized files). Weak by design.

**Risk score 0–100** = Σ(weight × risk) over the 5 indicators, normalised.
No black box: the report lists every indicator, its weight, its measured value,
its point contribution, and a plain-language interpretation with caveats.

## Measured results on the test images

Generated by `make_samples.py` — both are synthetic (labelled "SAMPLE IMAGE"),
no real person's data:

| image | what it is | risk score | ELA flags |
|---|---|---|---|
| `samples/clean_receipt.jpg` | synthetic receipt, single JPEG generation (q95) | **11.1** | none |
| `samples/tampered_receipt.jpg` | same image, but the amount `₹2,450.00` → `₹9,850.00` was **really composited** from a q50-compressed donor patch (simulating a forger pasting digits lifted from a forwarded screenshot), re-saved | **44.4** | **1 region: the forged amount block** (72,432)→(504,552), 52 cells, mean cell error 2.42 |

Heatmaps: `samples/ela_clean.png` (uniform text glow, no boxes) vs
`samples/ela_tampered.png` (forged amount block glows brightest + green box).
Reproduce any time with:

```bash
python3 forensics.py samples/clean_receipt.jpg samples/ela_clean.png
python3 forensics.py samples/tampered_receipt.jpg samples/ela_tampered.png
```

## Known limitations (stated plainly)

- ELA thresholds were **calibrated on the synthetic samples above**, not on real
  forgeries; real-world accuracy is unvalidated.
- A forgery edited and re-saved **in a single pipeline at one quality** is
  nearly invisible to ELA — this is a property of JPEG, not a bug.
- Layout heuristics cover 3 apps and are structural only.
- Screenshots shared as PNG (no JPEG tables) skip the self-consistency pass.
- This is a student-built screening aid, not a forensic lab.

## Files

- `app.py` — Flask web UI (upload → report)
- `forensics.py` — all checks + risk score; also a CLI
- `make_samples.py` — generates the two test images (real pixel edits)
- `samples/` — test images + ELA heatmaps
